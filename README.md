# gigacrew

Консольная утилита для работы с кодом локального проекта: навигация по исходникам, поиск, правка файлов и запуск команд в терминале.
Перед запуском скопируйте `.env.example` в `.env` и укажите в нём адрес API, модель и реквизиты доступа — значений по умолчанию нет.

## Установка

```sh
uv tool install gigacrew
# или
pipx install gigacrew
```

## Подтверждение команд

Команды, которые только читают проект (`ls`, `cat`, `grep`, `rg`, `git status/log/diff`,
однострочники на Python, которые лишь читают файлы), выполняются без вопроса в любом режиме.
Остальное gigacrew спрашивает и объясняет, почему: тесты и сборка исполняют код проекта,
установка пакетов идёт в сеть, `rm -rf` и `git push --force` — опасны. Классификатор работает
локально, без сети и моделей: команда разбирается деревом tree-sitter-bash, Python-код —
модулем `ast`. Всё незнакомое считается непроверенным, и решает пользователь.

На вопрос можно ответить:

- `y` — выполнить один раз;
- `a` — выполнить и запомнить для проекта. Программа с подкомандой (`pytest`, `npm test`)
  запоминается вместе с безопасными аргументами, а также в обёртках вроде
  `pytest -q 2>&1 | tail` или `uv run pytest`. Остальное запоминается как точная команда.
  Разрешение действует в своём рабочем каталоге. Опасное не запоминается;
- текстом — отказаться и сказать, что сделать вместо этого (ответ получит модель).

Разрешения и журнал решений (что спросили, почему, что ответили, в каком каталоге и чем
кончилось) хранятся в `~/.gigacode/projects/`, а не в проекте. Поэтому репозиторий не может
принести с собой готовые разрешения. `/permissions` показывает разрешения,
`/permissions forget N` удаляет одно, `/permissions log` показывает последние решения.
Журнал не ведётся с `--no-save`; секреты в командах (`TOKEN=…`, пароли в URL) вырезаются.

## Скиллы

Скилл — готовая инструкция для типовой задачи: файл `SKILL.md` в своём каталоге.
gigacrew ищет скиллы в `.gigacode/skills/<имя>/SKILL.md` проекта и в `~/.gigacode/skills/<имя>/SKILL.md`
(общие для всех проектов; при совпадении имён побеждает проектный).

```markdown
---
name: release
description: Как выпустить новую версию пакета
---
Подними версию в pyproject.toml, обнови CHANGELOG и поставь тег. Версия: $ARGUMENTS
```

Вызов — `/release 1.2.0` (Tab дополняет имена скиллов, `/help` их перечисляет; аргументы
подставляются вместо `$ARGUMENTS` или дописываются в конец). Модель видит список скиллов с описаниями
и может загрузить подходящий сама. Каталог `.gigacode/skills/` коммитится вместе с проектом — чаты,
история и индекс в той же папке закрыты её собственным `.gitignore`.
